# Catalog detail saves
- With Google account settings enabled, the detail button can save directly to an existing account, or initiate Google OAuth with a save intent for that exact detail. The callback verifies the session before making an idempotent private write. Ordinary sign-in does not copy local saves.
- Existing browser bookmarks and Naver import archives are separate and are not migrated, deleted, or automatically published. Cards outside the detail page still use the legacy browser bookmark flow. The archive shows account detail saves in a separate section.
- Deploy the additive `202611260001_kult_catalog_saves.sql` in a staging Supabase after the existing account migration. Confirm the staged site's exact `KULT_SITE_ORIGIN` and callback URL provider allowlist. No service key is needed.
- Stage with two consenting test accounts. In a clean private window open `/cafe/lowkey-seongsu`, save through Google, verify the exact route and pressed saved state, then view `/archive` on a fresh browser using the same login. Sign in as the second account and confirm the first account's space is absent. Verify repeated saves are a single row, an intentional removal affects only the signed-in account, and cancellation leaves the detail with a fallback. Verify the old browser save and Naver import still work without configuration.
- `node --test tests/*.test.mjs` exercises synthetic OAuth and API routes. Set `KULT_PGLITE_MODULE` to the path of a locally installed `@electric-sql/pglite` entry point to also apply both account SQL migrations in a disposable DB and verify access rules with synthetic users.
