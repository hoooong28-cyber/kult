# P1: People ↔ Place ↔ Story

## 기준과 실제 차이
- 기준: origin/main 64f6d8f. 기존 kult 작업 폴더의 미커밋 전체 리뉴얼은 보존하고 kult-p1에서 분리 작업.
- 최신 저장소에는 lib/stories.ts와 Story route, 공통 Interaction 모듈이 없었음.
- 실제 인증은 없으며 localStorage 프로필/이메일만으로 동작하는 데모 로그인임.
- Place/Curator JSON, 기존 /cafe route, Archive, Follow, NAVER import와 지도는 유지.

## 추가한 흐름
- 카드/장소 상세/Story의 공통 저장 버튼. 기존 로그인 요구 유지, 로그인 후 요청한 저장 재개, aria-pressed/44px 터치 영역/실패 및 성공 알림.
- 기존 저장/팔로우 키 보존. 새 브라우저에 가짜 저장·팔로우를 자동 생성하지 않음. 손상 데이터 및 저장 실패 시 덮어쓰거나 성공 이벤트를 만들지 않음. 다른 탭의 변경도 반영.
- Story 데이터의 place_ids/curator_ids 양방향 조회와 /story/[id], 관련 Story 카드, Curator 팔로우 버튼.
- 기존 큐레이터 기록을 연결한 편집 노트 2편. 새 인터뷰/방문 후기/셀럽의 발언을 생성하지 않음.
- 홈 구조는 유지하고 Story 섹션 추가. 앤트러사이트 소개에서 Cuco를 저장하던 잘못된 CTA는 Story 링크로 변경.

## 이벤트 계약
localStorage `kult_interactions_v1`, sessionStorage `kult_session_id`.
각 이벤트: id, event, occurred_at(UTC ISO), schema_version, user_id, session_id, 해당 place_id/story_id/curator_id, recommendation_source.
실제 서버 인증이 없으므로 현재 user_id는 항상 null. 로컬 프로필 ID를 실제 사용자 ID로 오인하지 않음. 향후 서버 세션 검증 경계에서 연결해야 함.
- impression: 카드가 50% 이상, 활성 탭에서 1초 노출. 해당 마운트당 1회.
- open/view: 실제 상세 페이지 마운트 시. 링크 클릭 자체로 미리 생성하지 않음.
- save/follow: 저장소 쓰기 성공 후만 기록.
- story_read: 본문이 보이는 활성 탭에서 누적 20초 이상 + 본문 끝에 도달. 완독의 확정값이 아닌 정의된 읽기 신호.
- map_open: 지도 확장 버튼 또는 네이버 지도 링크를 실제로 클릭.
- share: 네이티브 공유 또는 링크 복사 성공 시. 취소는 기록하지 않음.
- source는 실제 구현된 editorial/story/curator/curated_list/map/search만 허용. 직접 방문은 생략. 허위 taste_match/trending 이벤트 없음.
로그 실패는 핵심 동작을 막지 않으며 기존 로그를 삭제/회전하지 않음. 저장 한도에 도달하면 신규 기록 실패 가능. 서버 수집은 별도 승인 범위.

## 검증
- npm run build 통과: 최신 기준, 기능 연결, 모바일 수정 후.
- node --experimental-strip-types --test tests/*.test.mjs: 16개 통과.
- 최신 main은 단일 NAVER 장소 링크를 지원하지만 이전 테스트는 거부를 기대했음. 테스트를 현재 동작에 맞춰 수정; 가져오기 로직은 변경하지 않음.
- 실제 브라우저: 비로그인 저장 → 로컬 테스트 로그인 → 저장 재개, 새로고침 유지, Curator 이동/팔로우, Story 이동, 다른 Place 이동(source=story), 저장 → Archive 2곳 확인.
- 390×844 모바일 설정(브라우저가 보고한 content width 375)에서 Story 가로 넘침 수정 및 scrollWidth=clientWidth 확인. 1280×900 데스크톱 Story 연결 카드 확인.
- 로컬 지도는 SDK 대체 UI로 표시됨. production 도메인에서 지도 인증/타일 표시 및 실제 외부 네이버 응답은 별도 배포 검증 필요.
